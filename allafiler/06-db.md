## Fil 06: src/db.ts
Kopplingen till databasen. Alla services använder den för att skicka SQL till PostgreSQL.

## Hur den hänger ihop
services (`customerService.ts`, `orderService.ts`) → **den här filen** → PostgreSQL

## Koden

```ts
import { Pool } from "pg";

export const db = new Pool({
  connectionString:
    process.env.DATABASE_URL ?? "postgresql://postgres:postgres@localhost:5432/butik",
});
```

| Del | Vad den gör |
|---|---|
| `import { Pool } from "pg"` | Hämtar `Pool` från paketet `pg`. `pg` låter Node prata med PostgreSQL. |
| `new Pool(...)` | Skapar en pool: flera öppna kopplingar till databasen som återanvänds. Snabbare än att öppna en ny koppling varje gång. |
| `connectionString` | Adressen till databasen. |
| `process.env.DATABASE_URL` | Läser adressen från `.env`. |
| `?? "postgresql://..."` | Om adressen saknas används en standardadress. |
| `export const db` | Andra filer får använda `db`, t.ex. `db.query(...)`. |

## Adressen, del för del

`postgresql://postgres:postgres@localhost:5432/butik`

| Del | Betyder |
|---|---|
| `postgresql://` | Typ av databas |
| `postgres` (första) | Användarnamn |
| `postgres` (andra) | Lösenord |
| `localhost` | Min egen dator |
| `5432` | Porten |
| `butik` | Databasens namn |

Samma delar som jag fyller i när jag kopplar upp i pgAdmin.

## Skiljetecknen `:` och `@`

En adress är en lång rad text. Datorn behöver veta var en del slutar och nästa börjar. Därför finns **skiljetecken**: tecken som delar upp texten i bitar. De är **inte** en del av användarnamnet eller lösenordet.

Mönstret: `användare:lösenord@dator`

Exempel med olika ord: `postgresql://anna:hemligt123@localhost:5432/butik`

| Text | Vad det är |
|---|---|
| `postgresql://` | Typ av databas |
| `anna` | Användarnamn |
| `:` | Skiljetecken. Här slutar användarnamnet, och lösenordet börjar. |
| `hemligt123` | Lösenord |
| `@` | Skiljetecken. Här slutar lösenordet, och datorns namn börjar. |
| `localhost` | Datorn där databasen finns |
| `:` | Skiljetecken. Här kommer porten. |
| `5432` | Porten |
| `/` | Skiljetecken. Här kommer databasens namn. |
| `butik` | Databasens namn |

**Samma som i e-post:** i `anna@example.com` står vem före `@` och var efter `@`. I databasadressen står vem du är (användare och lösenord) före `@`, och var databasen finns efter `@`.

**I projektets adress** (`postgres:postgres@...`) är användarnamnet `postgres` och lösenordet också `postgres`.

## Risker
- 🟡 Ett lösenord står direkt i koden (`postgres`) som reservadress. Kodstandarden säger: inga lösenord i koden. Om `DATABASE_URL` saknas på en riktig server försöker appen ändå koppla upp med det. Lösning: ta bort reservadressen och stoppa appen med ett tydligt fel om `DATABASE_URL` saknas.
